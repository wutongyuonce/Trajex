# Trajex 未提交改动重构总结

> 本文总结当前工作区尚未 commit 的全部改动，按跨层改动、`packages`、`app`、测试与文档分组。统计基线：102 个已跟踪文件发生变化，另有若干新增分析文档；总体约 1,662 行新增、13,636 行删除。

## 一、整体方向

这批改动主要有四条主线：

1. 收缩产品范围：移除 Kimi Provider 和 Recap 功能。
2. 统一 Provider → canonical `TranscriptRecord` → SQLite → App 展示的数据链路。
3. 调整 Claude/Codex 的 transcript 解析语义，尤其是 summary、子代理和 Codex thread 的归属。
4. 升级 Electron 构建依赖，补齐 App 打包文档，并清理旧的项目分析/Recap 文档。

## 二、同时影响 `packages` 与 `app` 的改动

### 2.1 Provider 范围收缩

- Trajex 支持范围从 Claude、Codex、Kimi、Pi 收缩为 Claude、Codex、Pi。
- 删除 Kimi adapter、Kimi package export、Kimi registry 装配和相关类型说明。
- 删除 Kimi 的解析、运行时、App 索引测试。
- README、CONTEXT、Skill API/schema/retrieval 文档同步移除 `kimi` 来源说明。

涉及位置：

- `packages/core/src/providers/kimi.ts`
- `packages/core/src/providers/builtins.ts`
- `packages/core/package.json`
- `tests/*kimi*`
- `README.md`、`README.en.md`、`CONTEXT.md`

### 2.2 Summary 成为详情时间线的一等数据

- `summaries` 表新增 `agent_id`，旧数据库通过迁移补列。
- Core 持久化层写入 summary 的 `agent_id`。
- 主会话查询只返回 `agent_id IS NULL` 的 summary。
- 子代理详情新增 summary 查询和展示。
- Session Detail 时间线将 summary 与普通消息按时间排序，并支持折叠/展开。
- Claude compact summary、Codex `context_compacted`、Pi compaction/branch summary 都可以进入这条链路。

### 2.3 Canonical Session Detail 组装链路扩展

`packages/core/src/session-detail.ts` 继续作为唯一详情组装 seam，并新增：

- `tool_call.subagent` 关联信息。
- 通过 `parent_tool_use_id` 将 tool call 和 subagent 重新挂接。
- App 的 Agent tool call 展示中可以跳转到子代理详情。

对应 App 侧：

- `preload` 暴露 `getSubagentSummaries()`。
- `data.js` 同时加载子代理消息、工具调用、工具结果和摘要。
- `SubagentDetail.vue` 展示子代理 summary。
- `SessionTimelineRow.vue` 对关联 Agent tool call 增加详情入口。

### 2.4 数据源和构建边界同步调整

- App、CLI、Core、Skill 文档统一 Provider 列表。
- App 设置页从运行时返回并显示 `app.getVersion()`。
- App 继续直接消费 `packages/core/src`，Core 仍负责跨 Provider 的 canonical record、SQLite schema、持久化和查询。
- 根 `tsconfig` 不再排除已经删除的 Recap capture 测试。

## 三、`packages` 重构

### 3.1 Core Provider 解析模型

#### Claude

- 不再监听或读取 `history.jsonl`。
- session 标题改由 transcript 内的 `ai-title` 记录提供。
- `user` 记录中的 compact summary 会写入 `summaries`。
- 子代理 summary 会携带 `agent_id`。
- Claude workflow 目录中的 `journal.jsonl` 被视为日志而非 transcript，发现阶段跳过。
- Claude Workflow 的 `parent_tool_use_id` 只按 workflow JSON 的唯一 `runId` 回查主会话；不再用可重复的 `workflowName` 作为兜底，避免同名 workflow 误关联到旧调用。
- `parsing.ts` 中 Claude 专用的文本、内容类型、meta、工具路径处理函数重新归区。

#### Codex

- 继续全量读取单个 root rollout，以便处理 `event_msg` 与 `response_item` 的双向去重。
- 带有 `parent_thread_id` 的普通子代理 JSONL 在 discover 阶段被过滤，不再进入 parse/persist。
- Guardian/auto-review 线程仍会被识别，并通过 `delete-session` 撤回旧索引。
- 删除由 `collab_agent_spawn_end` 合成 `Agent` tool call/subagent 的旧逻辑。
- 新增 `context_compacted` summary。
- 清理 `<image>...</image>` 图片占位标记，保留可见文本。
- 每个 Codex thread 现在按自身 thread ID 成为独立 session。

#### Pi

- summary 的 `source` 改为实际 entry 类型，而不是统一使用 provider 名称。

### 3.2 共享解析和索引基础设施

- `readLines()` 使用 `StringDecoder` 处理跨 buffer 的 UTF-8 字符，避免多字节字符被拆断后产生替换字符。
- 共享解析函数按公共、Claude、Codex、索引收尾层重新组织。
- Provider index plan、迁移 marker、persist 和 session detail 的注释与类型契约补充完善。
- `deleteSession()` 现在会同时删除关联 memories。
- `SqliteDb`、`SqliteStatement`、`NodeSqliteDb` 等边界类型增加说明，继续隔离 `node:sqlite` 和 `better-sqlite3`。

### 3.3 Schema 和查询层

- `summaries.agent_id` 加入 `schema.sql` 和 additive migration。
- Provider 来源注释从 `claude/codex/kimi` 更新为 `claude/codex/pi`。
- 查询 API 的过滤项、只读 SQL、FTS 安全查询、memory 英文校验等接口说明更完整；核心行为总体保持不变。
- Core 版本标记保证 Provider 解析语义变更后触发全量重放。

### 3.4 CLI

- CLI README 移除 Kimi 说明。
- `packages/cli/package.json` 版本从 `0.2.1` 改为 `0.2.0`。
- build 脚本注释明确 npm `prepack → npm run build` 发布链路；构建产物仍包含编译后的 Core 和 `schema.sql`。

### 3.5 需要留意的迁移问题

Codex 新逻辑会跳过普通子代理 JSONL，但 Provider marker 全量重放本身不会清理旧的子代理派生行。已有数据库若曾使用旧逻辑索引 Codex，可能需要显式 force rebuild，或补充一次针对旧 Codex 子代理数据的清理迁移。

## 四、`app` 重构

### 4.1 移除 Recap 产品链路

删除或移除：

- Recap 路由：`/recap`、`/recap/:id`、`/recap-export`。
- Recap 列表、详情、导出页面。
- 五种 Recap card 组件、样式、archetype/seal 资源。
- Recap mock JSON 和 capture query。
- 主进程 PNG 导出、剪贴板复制、Recap 文件读取、Recap 文件监听 IPC。
- Settings 中的 Recap 输出目录配置。
- App sidebar、toolbar、breadcrumb 中的 Recap 入口。
- Skill 中的 Recap references 和对应测试。

这使 App 回到 sessions、memories、activity、settings 四类主要功能。

### 4.2 Session / Subagent 展示

- Session timeline 新增 summary 时间线项，按 timestamp 与消息排序。
- Summary 支持折叠/展开，主会话和子代理详情均可查看。
- Agent tool call 展示 `description`，提供 “View Agent details” 跳转。
- `apply_patch` 工具使用专门的 Patch 展示格式，工具参数预览可以从 patch 文本提取文件名。
- 文件内容渲染器支持自定义标题，并增加非对象值保护。
- 终端命令文本颜色调整为白色。
- 修复 timeline summary 合并时的全局排序问题：消息保持 transcript 原始顺序，summary 按时间稳定插入；相同/缺失时间不再通过 key 字典序重排消息。
- 同步测试契约：Claude 只保留 compact summary；Codex 子线程按独立线程跳过关联展示；Session Detail 验证 tool call 的 subagent 关联；schema 稳定性哈希更新。

### 4.3 后台索引与 IPC

- 移除 App 主进程额外的 `.md/.json` Recap watcher。
- Provider session watcher/indexer service 仍保留，负责会话数据刷新。
- 新增 `db:getSubagentSummaries` IPC，并通过 preload 白名单暴露。
- 主会话 summary 查询过滤掉子代理 summary，避免主时间线重复展示。

- Electron：`^33.0.0` → `^43.2.0`。
- electron-builder：`^25.0.0` → `^26.15.3`。
- App homepage/作者信息更新。
- `electron-vite` 配置移除 Recap capture entry。
- App lockfile 大幅重生成。
- README 新增 build、pack、macOS DMG/ZIP 产物说明。

## 七、当前改动的结果

改动完成后，项目目标形态是：

```text
Claude / Codex / Pi transcript
            ↓
Provider adapter
            ↓
canonical TranscriptRecord
            ↓
shared SQLite schema + FTS + memory
            ↓
CLI query / Electron session timeline
```

产品侧删除了 Kimi 和 Recap 两条支线，核心侧强化了 Provider 统一解析和 Session Detail 组装，App 侧把 summary、subagent 和 tool call 关系纳入同一条可浏览时间线。
